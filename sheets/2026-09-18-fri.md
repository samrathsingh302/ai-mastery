### 3. `ex05_unit_tests.py` — the rung where YOU write the test

- **File:** `C:\Users\samra\repos\ai-mastery\modules\03-cs50p-accelerated\exercises\ex05_unit_tests.py`
  (if `ex04_libraries.py` carried over from Thursday, finish it first — the ladder is in order).
- **What:** the file gives you two `median` implementations, one correct and one with a planted
  bug. You write `test_median(median)` so it stays **silent** on the good one and **raises
  AssertionError** on the buggy one. A test that passes on both is decoration, not protection.
- **A different worked example of the same idea** — testing a `clamp`:

  ```python
  def test_clamp(clamp):
      assert clamp(5, 0, 10) == 5      # ordinary case
      assert clamp(-3, 0, 10) == 0     # below the floor  <- the boundary
      assert clamp(99, 0, 10) == 10    # above the ceiling <- the boundary
  ```

  The middle case is why the test has teeth: **a good test hits the boundary**, because that is
  where implementations differ. Ask yourself where odd-length and even-length lists behave
  differently — that is the boundary here.
- **Check (from `C:\Users\samra\repos\ai-mastery`):**

  ```
  python modules\03-cs50p-accelerated\exercises\check.py ex05
  ```
- **Done when:** green. If it says your test *passes* the buggy implementation, your asserts never
  touch the even-length case; if it says your test *rejects* the good one, an assert is wrong.
