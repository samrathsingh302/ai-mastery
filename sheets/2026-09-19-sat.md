### 3. `ex06_files.py` — reading and writing files without leaking handles

- **File:** `C:\Users\samra\repos\ai-mastery\modules\03-cs50p-accelerated\exercises\ex06_files.py`
- **What:** `word_frequencies(path)` reads a text file and returns `{lower-cased word: count}`,
  whitespace-split, with `.,!?;:` stripped from each end and empties dropped;
  `write_then_read(path, lines)` writes each string on its own line, reads the file back, and
  returns the lines without their newlines. The checker hands you a temporary folder — **never
  hard-code a path**.
- **A different worked example of the same two moves** — counting the lines in a log:

  ```python
  def line_count(path):
      with open(path, encoding="utf-8") as f:   # `with` closes the file even if this blows up
          return sum(1 for _ in f)              # iterating a file yields its lines

  def append_note(path, note):
      with open(path, "a", encoding="utf-8") as f:   # "a" appends, "w" TRUNCATES first
          f.write(note + "\n")                       # write() adds no newline of its own
  ```

  Three things to carry across: `with` is how you never leak a handle · `"w"` destroys what was
  there and `"a"` does not · `write()` does not add the newline, you do. For the counting half,
  `dict.get(word, 0) + 1` is the idiom — the dictionary miss you carded on 27/08.

- **What:** `find_dates(text)` returns every `dd/mm/yyyy` string in order (two digits, slash, two
  digits, slash, four digits — no calendar validation); `extract_usernames(text)` returns the part
  before the `@` of every email-shaped token.
- **A different worked example** — pulling `HH:MM` times out of a line:

  ```python
  import re
  TIME = re.compile(r"\b(\d{2}):(\d{2})\b")          # raw string ALWAYS; \b = word boundary
  re.findall(r"\b\d{2}:\d{2}\b", "on at 09:30, off 17:05")   # -> ['09:30', '17:05']
  TIME.findall("on at 09:30")                        # -> [('09', '30')]  <- groups change the shape
  ```

  The one rule that catches most beginners: **`findall` returns the groups, not the match, as soon
  as the pattern has a group.** That is exactly the lever `extract_usernames` needs — put `( )`
  around the part you want back.

### 6. LPN chapter 3 — Recursion

- **Read:** https://lpn.swi-prolog.org/lpnpage.php?pagetype=html&pageid=lpn-htmlch3 — "Recursion"
  (§3.1 Recursive Definitions · §3.2 Rule Ordering, Goal Ordering and Termination · §3.4 Practical
  Session).
- **The one idea:** a recursive predicate needs **a base clause that stops** and **a recursive clause
  that moves toward it**, and in Prolog the *order you write them in decides whether it terminates*.
  Written base-first, `ancestor(X, Y) :- parent(X, Y).` then
  `ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).` terminates; flip the goals inside the second
  clause to put `ancestor` first and the engine recurses before it has any facts to stand on, forever.
  That is the difference between §3.2's *rule ordering* and *goal ordering*, and it is the chapter's
  whole payload.
- **Scratch file:** `C:\Users\samra\repos\ai-mastery\prolog\lpn-ch3.pl` (creates).

- **Done when:** you have written one recursive predicate of your own, predicted its answer before
