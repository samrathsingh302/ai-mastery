# Exercise 01 — Design four tasks of your own (the skill under the harness)

**Rules:** add FOUR tasks to a copy of tasks.json (`tasks-mine.json`) — two programmatic,
two rubric — drawn from what YOU actually ask models for (study explanations, commit
messages, PowerShell one-liners, Punjabi translations, whatever's real). ~45 min.

Each task must pass this checklist (the module's real content):

- [ ] **Representative** — you have genuinely wanted this from a model this month
- [ ] **One skill** — a failure tells you WHICH capability missed, not "something went wrong"
- [ ] **Verifiable** — programmatic: a checker can decide; rubric: criteria a stranger could
      apply and reach your score ±0
- [ ] **Crisp** — instruction so unambiguous that a wrong answer can't blame the prompt
      (read it as a hostile lawyer: what could a model do that technically complies?)
- [ ] **Uncontaminated** — not a famous puzzle whose answer is memorised text

Then the self-check that matters: for each task, WRITE DOWN the failure you expect the
weaker model to make. If you can't predict a plausible failure, the task is probably too
easy to discriminate — sharpen it.

**Solutions folder** has my four-example set with the checklist applied and one deliberately
BAD task per category, annotated with why it's bad (`solutions/ex01-examples.md`).
